[갑자기 제조 데이터 말고 EPL 데이터 크롤링을 한다고?]

자. 제조데이터만 하던 제가 갑자기 EPL 선수, 매치 데이터를 크롤링해서,

스카우터들에게 참고하기 유용한 대시보드를 만들고 싶다는 생각이 문득 들었습니다!

처음에는 단순히 "선수 스탯을 모아보자" 정도로 시작했는데, 막상 뜯어보니 생각보다 일이 꽤 커졌습니다.

매치 결과 데이터, 선수 시즌 스탯, 선수별 경기 로그, 시장가치 데이터가 각각 따로 존재했고,
이걸 하나의 분석 흐름으로 묶어야 "누가 잘하는지"를 넘어서
"누가 저평가되어 있는지", "누가 성장 가능성이 있는지"까지 볼 수 있겠더라고요.

이번 1편에서는 아래 4가지를 중심으로 정리해보려고 합니다.

1. 문제를 어떻게 정의했는지
2. 데이터를 어떻게 크롤링했는지
3. EDA에서 어떤 패턴을 봤는지
4. 전처리에서 어떤 기준으로 데이터를 정리했는지

**1. 문제를 어떻게 정의했는지**

처음에는 단순히 "선수 스탯을 조회할 수 있으면 되지 않을까?"에서 출발했습니다.
그런데 조금만 더 들여다보니, 진짜 필요한 건 단순 조회용 데이터가 아니라
"스카우터가 참고할 수 있는 분석용 데이터셋"이라는 생각이 들었습니다.

매치 결과 데이터, 선수 시즌 스탯, 선수별 경기 로그, 시장가치 데이터가 각각 따로 놀고 있었고,
이걸 하나로 묶어야 "누가 잘하는가"를 넘어서
"누가 저평가되어 있는가", "누가 성장 가능성이 있는가"까지 확장할 수 있겠다고 봤습니다.

그래서 이번 프로젝트의 첫 목표를
"EPL 선수와 경기 데이터를 직접 수집하고, EDA와 전처리를 거쳐 스카우팅용 데이터 기반을 만든다"
로 잡았습니다.

**2. 데이터를 어떻게 크롤링했는지**

데이터 소스는 FBref와 Transfermarkt를 중심으로 구성했습니다.

FBref에서는 시즌별 리그 페이지에서 팀 링크를 수집하고,
각 팀 페이지에서 선수 시즌 스탯을 가져온 뒤,
다시 선수별 match log까지 타고 들어가는 방식으로 데이터를 모았습니다.

Transfermarkt에서는 시장가치, 포지션, 국적, 주발, 입단일 같은
스카우팅에 유용한 메타 정보를 추가했습니다.

특히 이번 크롤링에서 중요하게 본 건
"한 번에 잘 긁기"보다 "중간에 실패해도 다시 이어서 돌릴 수 있게 만들기"였습니다.

그래서 체크포인트 기반 재시작 구조를 넣고,
사이트별로 요청 간격도 다르게 설정했습니다.
이런 부분은 초반에는 사소해 보여도,
여러 시즌 데이터를 반복 수집할 때 체감 차이가 꽤 컸습니다.

크롤링에는 생각보다 많은 시간이 들었고,
그 과정에서 "재시작 가능한 구조"의 중요성을 정말 크게 느꼈습니다.

**3. EDA에서 어떤 패턴을 봤는지**

EDA에서는 단순히 분포를 보는 데서 끝내지 않고,
이 데이터가 EPL이라는 리그의 흐름을 얼마나 반영하고 있는지도 같이 확인해봤습니다.

첫 번째로 시즌별 경기당 평균 골 수를 보니,
리그 득점 환경이 최근 들어 확실히 더 공격적으로 바뀌고 있다는 흐름이 보였습니다.
특히 2023/24 시즌은 프로젝트 데이터에서도 뚜렷한 피크로 나타났는데,
실제로 프리미어리그 공식 기록에서도 이 시즌은 총 1,246골, 경기당 3.28골로 역대 최고 시즌이었습니다.
즉, 이 그래프는 단순한 시즌별 변동이 아니라
리그 환경 자체가 바뀌고 있다는 신호로 볼 수 있었습니다.

두 번째로 선수 연령 분포를 보면,
EPL 선수들이 24~29세 구간에 가장 많이 몰려 있었습니다.
외부 분석에서도 이 구간은 흔히 전성기(peak years)로 해석되는데,
우리 데이터 역시 비슷한 구조를 보여줬습니다.
또 포지션별로 보면 골키퍼는 상대적으로 고연령이고,
필드 플레이어들은 20대 중후반에 밀집하는 경향이 보여서,
이후 모델링에서는 나이를 단일 기준으로 보기보다
포지션과 함께 해석해야겠다는 판단을 하게 됐습니다.

세 번째로 결측치 현황을 보면서는
"비어 있는 값은 다 지우면 된다"는 접근이 위험하다는 걸 확인했습니다.
초기 시즌 match log에는 최근 시즌만큼 세부 이벤트 스탯이 풍부하지 않았고,
이는 단순 누락이라기보다 시즌별 제공 범위 차이에 가까웠습니다.
그래서 이번 전처리에서는 결측을 일괄 제거하기보다,
세부 스탯 가용 여부 자체를 하나의 정보로 보고 별도 플래그를 만드는 방향을 택했습니다.

결국 이번 EDA의 핵심은
예쁜 그래프를 그리는 것보다,
이 데이터가 어떤 시대적 맥락과 수집 한계를 갖고 있는지 이해하는 과정에 더 가까웠던 것 같습니다.

**4. 전처리에서 어떤 기준으로 데이터를 정리했는지**

전처리에서는 모델링보다 먼저
"이 데이터를 믿고 다음 단계로 넘어갈 수 있는가"를 기준으로 삼았습니다.

그래서 아래와 같은 작업들을 우선적으로 정리했습니다.

- 팀명 표준화
- 선수명 유니코드 정규화
- 경기 결과 문자열 파싱
- 자책골 의심 경기 플래그 생성
- 세부 스탯 가용 여부 플래그 생성
- 같은 시즌 여러 팀에 속한 선수 transfer flag 처리
- FBref 스탯과 Transfermarkt 시장가치 매칭

이 과정을 거치면서 느낀 건,
크롤링 프로젝트는 단순 수집이 아니라
데이터의 정의와 품질 기준을 세우는 작업에 더 가깝다는 점이었습니다.

다음 편에서는
이렇게 정리한 데이터를 바탕으로 어떤 파생변수를 만들었고,
왜 PIS(Player Impact Score) 같은 평가 지표와 시장가치, 성장/하락 리스크 모델로 확장했는지 정리해보겠습니다.
